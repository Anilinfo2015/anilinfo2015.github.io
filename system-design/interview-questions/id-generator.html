Unique ID generator

Requirements · Core entities · API or system interface · High-level design · Deep dives

1. Requirements

Functional requirements

Return a new identifier that is unique across the whole fleet; keep identifiers roughly time-ordered so they sort by creation; let many independent services allocate concurrently through a local library call.

Nonfunctional requirements

  1. NFR1: assume 1,000,000 IDs/second across the fleet, with p99 below 1 ms when serving from a local batch and below 10 ms when refilling from the coordinator.
  2. NFR2: never return one identifier twice, including across process restarts, backward clock steps, or one availability-zone failure.
  3. NFR3: keep identifiers k-sortable in 64 bits: two IDs generated more than one second apart must order by time.
  4. NFR4: target 99.99% allocation availability; a node must keep issuing from its reserved allotment during a coordinator outage.

Out of scope

Cryptographic unpredictability, using identifiers as bearer capabilities, and total ordering across datacenters are excluded. IDs reveal approximate creation time by design.

2. Core entities

NodeLease(nodeId, leaseEpoch, expiresAt) assigns a worker number to one process. IdLayout(timestampMs, nodeId, sequence) fixes the bit budget, for example 41 timestamp bits, 10 node bits, and 12 sequence bits. Allotment(service, blockStart, blockEnd) holds a durably reserved counter block for the ticket-server alternative. A (nodeId, leaseEpoch) pair must never be reused while its earlier IDs might still be forming.

3. API or system interface

Callers use a local next() -> id that never blocks on the network in the common path. The library backs it with POST /nodes/lease {serviceId} returning {nodeId, leaseEpoch, expiresAt}, renewed by heartbeat, or POST /allotments {serviceId, size} returning a counter block. Leasing requires service authentication. Return 409 when no node number is free, and 423 when the wall clock has moved backward beyond tolerance so the caller waits rather than risking a duplicate.

4. High-level design

flowchart LR
    Service --> IdLibrary
    IdLibrary --> Coordinator
    Coordinator --> MetadataStore
  1. On startup the library leases a node number (or a counter block) from the coordinator.
  2. next() composes timestamp || nodeId || sequence locally, incrementing the sequence within a millisecond.
  3. On lease expiry, sequence exhaustion, or a clock regression, the library re-leases or waits before emitting again.

5. Deep dives

Trade-offs and bottlenecks

A timestamp-plus-node-plus-sequence layout needs no coordination per identifier and stays sortable, but it assumes bounded clock skew and a finite node-number space. A central auto-increment ticket server is simple and gapless, yet every allocation crosses the network and the server caps throughput; handing out blocks amortizes that at the cost of gaps and weaker ordering. Random 128-bit UUIDs remove coordination entirely but are unsortable and hurt index locality.

Scale estimate: node fan-out and coordinator load

At 1,000,000 IDs/second with a 12-bit sequence, each node can mint 4,096 IDs/millisecond, about 4.1 million/second, so a handful of nodes covers peak; the 10-bit node field allows 1,024 of them. The block alternative with 100,000-value allotments needs only ten coordinator calls/second at this rate, each cached locally for sub-microsecond allocation. Lease and allotment metadata is kilobytes, so the coordinator is a coordination service, not a data-plane bottleneck.

Clocks, restarts, and uniqueness

Discipline node clocks with NTP and persist a per-node high-water timestamp on each lease renewal; on restart, resume above it so a reboot never rewinds. If the wall clock regresses within tolerance, refuse to emit and wait for it to catch up rather than reissue a lower timestamp. When a millisecond's sequence is exhausted, spin to the next millisecond instead of overflowing into the node bits. Size the lease TTL to exceed the longest possible in-flight emission window so a node that cannot renew stops issuing before its number could be reassigned.

Availability without a coordinator

Reserve node numbers or counter blocks with a TTL longer than the coordinator's expected outage, so allocation continues locally during a partition. Keep leases in a small, strongly consistent replicated store so two nodes never hold the same number, and fence renewals by lease epoch so a delayed renewal from a paused process is rejected. On total coordinator loss, nodes serve until their TTL expires and then fail closed, refusing new IDs rather than risking duplicates.

Check the design

NFR1 maps to local sequence and cached blocks; NFR2 maps to fenced leases plus the persisted high-water timestamp; NFR3 maps to the timestamp-high bit layout; NFR4 maps to TTL-reserved allotments. Test it by pausing a node past a long garbage-collection stall, stepping its clock backward 500 ms, and rebooting it: it must not emit any identifier less than or equal to one already issued, and its node number must stay unassigned until its lease expires.
