Web crawler

Requirements · Core entities · API or system interface · Data flow · High-level design · Deep dives

1. Requirements

Functional requirements

Submit public seed URLs; fetch pages and discover links within a job budget; retrieve job progress and captured pages. Jobs specify allowed domains, depth, page count, and byte budgets.

Nonfunctional requirements

  1. NFR1: assume 10,000 peak fetches/second and p95 eligible-frontier wait below 60 seconds under admitted load.
  2. NFR2: enforce at most one concurrent request and one request start/second per origin, or a stricter robots policy.
  3. NFR3: lose no acknowledged job or completed-page metadata after one worker or zone failure; repeated fetching is acceptable.
  4. NFR4: block all non-public network destinations and allow only job owners to access results.

Out of scope

Search ranking, authenticated websites, JavaScript execution, and bypassing paywalls or robots restrictions are excluded.

2. Core entities

Job(jobId, ownerId, budget), Frontier(jobId, normalizedUrl), Origin(originKey, nextAllowedAt), and Capture(jobId, url, fetchGeneration) are durable records. Normalize host case and fragments without assuming query parameters are interchangeable. An origin's scheduling lease must have only one valid holder.

3. API or system interface

POST /crawl-jobs {seeds, allowedDomains, maxPages, maxDepth} requires an authenticated principal and Idempotency-Key; return 202 {jobId}, 422 for invalid limits, or 409 for a reused key with different input. Identical retries return the job. GET /crawl-jobs/{id} returns counters/state. GET /crawl-jobs/{id}/pages?cursor&limit returns capture metadata and a continuation cursor, capped at 100 results. Every result endpoint checks ownership and returns 404 for inaccessible jobs. Downloads use short-lived owner-scoped URLs.

Data flow (optional)

Seeds enter a normalized, deduplicated frontier. Eligible URLs pass origin scheduling and network-policy checks before fetching; captured bodies yield stored results and new in-scope links. Discovered links re-enter the frontier within the job's depth, page, and byte budgets, while redirects also pass destination-origin scheduling.

5. Deep dives

Trade-offs and bottlenecks

A database frontier is easy to inspect and deduplicate, but scanning for work gets expensive. A plain FIFO queue scales dispatch yet lets a slow origin block useful work. Partition origin queues and index nextAllowedAt. Exact URL deduplication costs storage; a Bloom filter alone would silently skip some pages.

Scale estimate: body retention and ingress

Assume 100 million pages/day: 1,157 fetches/second on average. At 200 KB compressed per page, this is 20 TB/day before replicas; peak ingress is 2 GB/second. Seven-day body retention needs 140 TB raw. Use object storage and enforce byte budgets before expanding worker count; metadata belongs in a separate store.

Safe, polite scheduling

Hash origins to scheduler partitions; a durable, fenced lease controls each origin's start times. Robots retrieval consumes that budget; unreadable robots policies pause crawling. Stop dispatch when lease renewal fails; replacement owners wait for outstanding fetch deadlines before resuming. Apply Retry-After and backoff; paused origins are not eligible. Every redirect re-enters destination-origin scheduling. An egress proxy resolves and pins validated public IPs, rejects private/link-local IPv4 and IPv6 ranges, and repeats validation for every redirect. Disable ambient credentials and cap redirects, response bytes, and decompression. These checks prevent the crawler becoming an internal-network client.

Recoverable captures and private results

Workers write immutable blobs before committing capture metadata and new frontier rows in a replicated transaction. Retry using the same fetch-generation identifier; uniqueness prevents double-counting completed captures. Expired leases requeue work, so network fetches remain at-least-once. Sweep unreferenced blobs after a grace period. Store metadata across zones, encrypt bodies, and enforce job ownership at listing and download issuance. Download gateways verify caller identity against owner-bound capabilities; storage buckets are never public. Monitor oldest eligible work and reject new jobs when admitted capacity cannot meet the wait target.

Check the design

NFR1–2 map to safe, polite scheduling; NFR3 maps to recoverable captures; NFR4 needs both network-policy enforcement and private result access. Kill a worker after blob upload: one capture eventually appears. Redirect a test URL to a private address: observe a policy rejection and no outgoing private-network connection.
