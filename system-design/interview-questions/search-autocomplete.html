Design search autocomplete

1. Requirements

Functional: return ranked suggestions for a typed prefix; record selected suggestions to influence popularity; remove prohibited suggestions. Assume public suggestions grouped by language and region, not personalized histories.

Non-functional assumptions: N1: suggestion p99 below 50 ms server-side. N2: serve 50,000 requests/s peak over 20 million normalized phrases. N3: incorporate popularity updates within five minutes and enforce removals within 60 seconds.

2. Out of scope

Exclude typo correction, full search results, private content, and per-user ranking. Prefix matching begins at two normalized characters.

3. Core entities

Phrase uses (locale, phrase ID), with display text, normalized text, score, and moderation version. SelectionEvent has event ID, locale, and phrase ID. Snapshot uses (locale, generation). Removal uses (locale, phrase ID) and monotonic version. Older snapshots or events cannot resurrect a removal already applied by a serving node.

4. API

GET /suggest?prefix=&locale=&limit= returns up to ten phrase IDs and labels plus generation; no pagination is needed. Reject invalid locale or overlong prefixes with 400 and overload with 429. Anonymous callers receive scoped client tokens and quotas; administrative APIs require moderator roles. POST /selections accepts event ID, locale, and phrase ID, returning 202; same-ID retries deduplicate within seven days. DELETE /locales/{locale}/phrases/{id} returns a removal version and 202. Poll authorized moderation status for propagation; unknown IDs return 404. Read retries are safe.

5. Basic design

    Moderator --> API
  1. Normalize the prefix, select matching active phrases from a prefix index, and rank by score with phrase ID as a tie-breaker.
  2. Persist selection events; a periodic aggregator updates phrase scores.
  3. Mark moderated phrases removed; queries filter those rows before returning labels.

6. Trade-offs and bottlenecks

Indexed database queries keep freshness simple but sorting every popular prefix is expensive. Precomputed top suggestions bound read work at the cost of delayed popularity and rebuilding. Choose precomputation because keystroke traffic is much larger than phrase-update traffic.

7. Scale estimate

Assume 10,000 requests/s average and fivefold peak. At 500 bytes per response, peak egress is 25 MB/s before protocol overhead. Twenty million phrase records at 100 bytes occupy 2 GB raw, but trie nodes and candidate lists add memory. Measure that multiplier before sizing replicas; cache popular prefixes and split by locale plus prefix range rather than assuming a single 2 GB index.

8. Deep dive 1: Bounded serving work

N1/N2 use immutable compact tries with a precomputed top-50 candidate list at each prefix node. Traverse normalized Unicode code points, then filter removals and return ten; returning fewer is acceptable after heavy filtering. Split large locales by two-character prefix, keeping each supported query on one partition. Replicate hot partitions and cache by locale, prefix, and generation. On replica failure, route to another copy of the same generation; shed excess requests rather than falling back to unbounded database sorts. Load-test hot prefixes, not only uniform traffic.

9. Deep dive 2: Freshness and moderation

N3 deduplicates events into per-phrase, five-minute-window counters, capping client contributions. Rebuild changed prefix partitions every minute with four minutes reserved for building and atomic manifest publication. Resume failed builds from committed offsets. Broadcast durable removal versions and invalidate affected caches; a final response filter also removes cached candidates. The ordered removal stream includes authority-issued timestamped barriers. Serve only after applying a barrier less than 60 seconds old, including every preceding removal. Fresh heartbeats without applied progress do not qualify; lagging replicas stop serving.

10. Check the design

N1/N2 map to dive 1; N3 maps to dive 2. Block removal application while heartbeats continue: the replica must stop serving at the applied-barrier deadline. Replaying an older snapshot must not restore the removed phrase.
