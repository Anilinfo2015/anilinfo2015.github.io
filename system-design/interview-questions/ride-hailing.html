Ride hailing

1. Requirements

Functional: request a fixed-fare ride; let a driver accept and complete it; show the rider live trip progress.

  1. NFR1: assume 5,000 peak ride requests and 200,000 location updates/second; target candidate lookup p95 below 300 ms using positions at most ten seconds old.
  2. NFR2: assign at most one active driver per ride and one active ride per driver.
  3. NFR3: target 99.9% monthly booking availability and no loss of acknowledged assignments after one zone failure.
  4. NFR4: reveal precise tracking only to active trip participants; terminate access within five seconds of trip completion or removal.

2. Out of scope

Pooling, fare calculation, payment settlement, and route optimization are excluded. A pricing component supplies expiring fixed-fare quotes; location samples do not determine charges.

3. Core entities

Quote(quoteId, riderId, amountMinor, currency, expiresAt), Ride(rideId, riderId, driverId, state, version), Driver(driverId, activeRideId), and Position(driverId, sequence, observedAt) are core records. Offers have offerId and expiry. Assignment updates the ride and driver together; geographic candidates never constitute reservations.

4. API

POST /rides {quoteId, pickup, destination} requires rider authentication and Idempotency-Key; return 202 {rideId, state}. Identical retries reuse the ride; changed input returns 409, expired or mismatched quotes 422. POST /offers/{id}/accept permits only the offered driver and returns the assigned ride or 409 if expired/taken. POST /rides/{id}/complete {expectedVersion} is assigned-driver-only and idempotent by requestId. PUT /drivers/me/location {sequence, coordinates, observedAt} ignores older sequences. GET /rides/{id} and tracking subscriptions check participation; inaccessible rides return 404. Overload returns 429.

5. Basic design

  1. Store the rider's request and quote snapshot; find nearby available drivers.
  2. Send expiring offers; accepting commits the ride assignment and driver reservation atomically.
  3. Forward authorized location updates; completion releases the driver and closes tracking.

6. Trade-offs and bottlenecks

Sequential offers reduce contention but increase delay when drivers ignore them. Small parallel batches improve response time but require atomic winner selection. Geographic indexes are stale by construction; recheck availability in the assignment transaction.

7. Scale estimate

One million drivers updating every five seconds generate 200,000 updates/second. At 100 bytes/update, raw ingress is 20 MB/second, or 1.728 TB/day if retained. Keeping each driver's latest 200-byte position needs 200 MB raw before indexes and replicas. Use an ephemeral location pipeline, not transactional trip storage, for pings.

8. Deep dive 1: Fresh geographic discovery

Partition location updates by city and geographic cell, with neighboring-cell queries near boundaries. Apply only increasing device-session sequence numbers and reject implausibly future timestamps; server receipt times bound freshness. Expire positions after ten seconds, and overfetch candidates to compensate for stale availability. A cell handoff can briefly duplicate a driver, so deduplicate by driverId. Busy districts need finer cells and independent ingestion capacity. Push latest positions through bounded queues, dropping superseded samples instead of delaying current ones. Missing fresh drivers produces an honest no-candidate result, not a fabricated location.

9. Deep dive 2: Assignment authority and private tracking

Keep a city's rides and driver reservations in a quorum-replicated transactional partition. Conditional updates require an unassigned ride, idle driver, and unexpired offer; only one competing acceptance commits. Driver ownership moves between cities only while idle through a fenced transfer. Persist assignment and notification outbox together; replayed notifications cannot reassign a ride. A zone failover elects one fenced writer, while minority partitions reject acceptance. Tracking gateways validate participant identity and use five-second leases checked against active trip state; completion invalidates leases, and expiry covers missed events. The fixed quote snapshot remains immutable and uses integer minor currency units.

10. Check the design

NFR1 → dive 1; NFR2–4 → dive 2. Race two drivers accepting one ride while losing the leader: exactly one assignment survives, the losing driver remains available, and completion stops tracking within five seconds.
