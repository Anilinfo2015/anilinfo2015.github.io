Inventory Management

1. Requirements

Receive stock, reserve a set of items in one warehouse, ship a reservation, or release it. Concurrent service instances share transactional storage. Quantities are positive whole units, not floating-point measures. Limit reservations to 100 distinct SKUs. Reservations last fifteen minutes and are valid on [createdAt,expiresAt), using database time. Inventory operations do not price or charge orders.

2. Out of scope

Exclude cross-warehouse transfers, backorders, lot tracking, fractional quantities, procurement, and external payments. A reservation ships all its lines together; partial shipment is a separate extension. Expired allocations may remain conservatively reserved until a cleanup transaction releases them.

3. Model and invariants

InventoryService owns stock mutations. Balance, keyed by warehouse and SKU, owns onHand and reserved counts. Reservation owns immutable line quantities, expiry, and status HELD, SHIPPED, RELEASED, or EXPIRED. StockMovement records each committed receipt or shipment for audit.

Every balance satisfies 0 ≤ reserved ≤ onHand; available equals onHand minus reserved. Reserved equals quantities in reservations still marked HELD, including expired-but-not-cleaned records. Shipping consumes onHand and reserved together; releasing changes reserved only.

4. Public contract

receive(warehouseId, sku, quantity, receiptKey) → Movement returns NotFound, InvalidQuantity, Overflow, or KeyConflict. Identical receipt keys return the original movement, never a second increment. reserve(warehouseId, items, key) → Reservation returns NotFound, InvalidItems, InsufficientStock, or KeyConflict. Duplicate SKU lines are rejected rather than ambiguously combined; identical keys return the original reservation.

ship(reservationId) → Reservation is idempotent once shipped and otherwise returns NotFound, Expired, or InvalidState. release(reservationId) returns the existing released/expired record on retries, rejects shipped reservations with InvalidState, and unknown IDs with NotFound. availability(warehouseId, sku) → Counts returns a snapshot or NotFound.

5. Core flow

Reserve validates quantities and locks all requested balance rows in sorted SKU order. Recheck available quantities for every line. If any line is short, roll back without reserving the others. Otherwise increment reserved counts and insert the reservation plus deduplication result in one transaction.

Ship locks reservation first, then its balance rows in sorted order. Read database time after acquiring locks. At or beyond expiry, decrement reserved quantities, mark EXPIRED, commit, and return the expiry result. Otherwise decrement both counts, append movement records uniquely keyed by reservation and SKU, and mark SHIPPED atomically. Release and expiry cleanup take the same locks and decrement reserved exactly once.

6. Trade-offs and extensions

Separate onHand and reserved counters make availability cheap while preserving physical stock accounting. Conservative cleanup can temporarily understate availability, but cannot oversell. Partial shipment would require per-line shipped and released quantities plus operation keys, rather than reusing the all-or-nothing status.

7. Concurrency and failure handling

Balance locks protect multi-item allocation; reservation locks protect ship-versus-release races. Receipt uniqueness and reservation request keys survive process failure. A lost shipment response is safely retried by reservation ID. Physical dispatch is not performed inside the transaction: if integrated, publish a durable dispatch intent and deduplicate warehouse execution separately.

8. Test cases

With onHand=10, reserving 4 produces available=6; shipping produces onHand=6 and reserved=0. Reserving A=2 and unavailable B=1 changes neither balance. Two reservations for the last unit yield one success. Shipping exactly at expiry releases stock and returns Expired. Duplicate receipts increase stock once. Concurrent ship and release produce one terminal outcome. Reject 101 lines before acquiring balance locks.
