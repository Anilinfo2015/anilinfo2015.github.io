In-Memory Filesystem

1. Requirements

Create directories and files, read and replace bytes, list children, move entries, and remove empty directories or files. Multiple threads share one in-memory filesystem. Paths are absolute and case-sensitive. Bound total file content to 64 MiB, entries to 10000, and path depth to 128. Operations return copies rather than mutable internal objects.

2. Out of scope

Exclude disk persistence, permissions, symbolic links, hard links, recursive deletion, file handles, and append. Paths address entries at operation time; renaming an entry does not leave an alias. Bytes have no assumed text encoding. Replacement of an existing destination during move is deliberately unsupported.

3. Model and invariants

FileSystem owns the root, quota counters, and a read/write lock. A Directory owns a map from child name to entry. A File owns an immutable byte array; every non-root entry has exactly one parent and one name.

The tree contains no cycles, child names are unique within each directory, and quota counters equal reachable content and entries. The root cannot be moved or deleted. Every successful mutation preserves the maximum depth, including descendants of a moved directory.

4. Public contract

mkdir(path) and createFile(path, bytes) return entry metadata or AlreadyExists. read(path) → bytes, write(path, bytes) → metadata, list(path) → sorted metadata[], move(source, destination) → metadata, and remove(path) → void additionally return applicable NotFound, NotDirectory, IsDirectory, NotEmpty, InvalidMove, or QuotaExceeded. All reject invalid paths with InvalidPath. Parent directories must already exist. Create and remove retries return existing/not-found errors; writing identical bytes is harmless, but there is no request deduplication.

5. Core flow

Canonicalize paths before lookup: require a leading slash, collapse repeated separators and dot segments, resolve double-dot segments without traversing above root, and reject NUL and excessive depth. Trailing separators are ignored. Traverse directory child maps one component at a time.

For write, acquire the write lock, resolve a file, and check the replacement-size delta against the global quota. Allocate a defensive byte copy before swapping content and updating counters.

For move, resolve source and destination parent under the write lock. Reject an occupied destination, root source, or a destination parent inside the source subtree. Walk parent links to detect that cycle; inspect subtree height to check resulting depth. Preallocate the new map entry, then detach and attach atomically, updating parent and name. Content quota is unchanged.

6. Trade-offs and extensions

A global read/write lock makes cross-directory moves simple but blocks unrelated writers. Per-directory locking is a possible extension only with a consistent lock ordering and explicit protection against concurrent ancestor moves.

7. Concurrency and failure handling

Reads hold a read lock through snapshot creation; mutations hold the write lock through publication. Allocation failure leaves the tree and counters unchanged. A process crash loses all entries. A durable version would need a journal covering both sides of a move, not separate directory saves.

8. Test cases

Create /a and /a/x containing three bytes; reading returns those bytes without exposing storage. Moving /a to /a/b fails with no mutation. Removing nonempty /a fails. /a/./x and /a/x resolve identically; /../../x is invalid. Concurrent creates of /a/x yield one success. Replacing a 10-byte file with 20 bytes increases usage by ten. A move producing depth 129 fails before detachment.
